# Протокол интервью (Фаза 0)

Цель — за минимальное число вопросов зафиксировать скоуп, достаточный для запуска
потоков-агентов. Один-два вопроса за раз через `AskUserQuestion`. Не спрашивай то, что уже
известно из сообщения пользователя.

## Шаг 1. Restate (без вопросов)

Переформулируй идею одним абзацем: *что* за продукт/решение, *для кого*, *какую проблему*
закрывает. Если заявленная формулировка проблемы выглядит неточной — предложи уточнённую
(напр. «почему не строится» → «почему не находит застройщиков»). Заверши: «Правильно понял?
Поправь, если нет».

## Шаг 2. Волны вопросов

**Волна 1 — проблема и контекст**
- Кто страдает от проблемы (благополучатели, ЦА)? Кто платит?
- Тип проекта: (а) строительное решение, (б) ИТ-продукт ДЛЯ стройки → «двойной пресейл»
  (предметная проблема + техрешение), (в) чистое ИТ.

**Волна 2 — границы и контекст реализации**
- Антископ: что в этом исследовании НЕ рассматриваем?
- Нормативный/рыночный контекст: РФ (СП/ГОСТ/ФЗ) или другой рынок? Известные ограничения?
- Есть ли уже гипотеза про ИИ внутри продукта (или это и нужно проверить)?

**Волна 3 — параметры прогона**
- Глубина: **быстрая** (≈4 потока, без глубокого веб-поиска) или **полная** (потоки +
  `deep-research` + аудит в 2 голоса)?
- Язык итогового отчёта (по умолчанию русский).

## Шаг 3. Фиксация скоупа

Выведи короткое резюме скоупа (идея, ЦА, тип, антископ, контекст, глубина, язык) и получи
явное «поехали». Только после этого — Фаза 1.

## Подсказки по pushback

- Слишком широкая идея → попроси сузить до одного измеримого сценария.
- «Хотим ИИ в продукте» без причины → отметь, что это проверит поток D (этап 4), не принимай на веру.
- Нет ЦА/проблемы, сразу решение → верни к проблеме (этап 1 без неё не имеет смысла).
