# Interview protocol (Phase 0)

Goal — with the fewest questions, lock a scope sufficient to launch the agent streams. One or
two questions at a time via `AskUserQuestion`. Don't ask what the user already told you.

## Step 1. Restate (no questions)

Rephrase the idea in one paragraph: *what* the product/solution is, *for whom*, *which
problem* it closes. If the stated problem framing looks inaccurate — propose a sharper one
(e.g. "why isn't it being built" → "why isn't it attracting developers"). End with: "Did I get
it right? Correct me if not."

## Step 2. Waves of questions

**Wave 1 — problem and context**
- Who suffers from the problem (beneficiaries, audience)? Who pays?
- Project type: (a) construction solution, (b) IT product FOR construction → "double
  pre-sales" (domain problem + tech solution), (c) pure IT.

**Wave 2 — boundaries and delivery context**
- Anti-scope: what is NOT considered in this study?
- Regulatory/market context: which market and codes/standards apply? Known constraints?
- Is there already a hypothesis about AI inside the product (or is that exactly what to test)?

**Wave 3 — run parameters**
- Depth: **quick** (≈4 streams, no deep web search) or **full** (streams + `deep-research` +
  dual-voice audit)?
- Output language (default English).

## Step 3. Lock the scope

Print a short scope summary (idea, audience, type, anti-scope, context, depth, language) and
get an explicit "go". Only then proceed to Phase 1.

## Pushback hints

- Idea too broad → ask to narrow to one measurable scenario.
- "We want AI in the product" with no reason → note this will be tested by stream D (stage 4); don't take on faith.
- No audience/problem, jumping to a solution → return to the problem (stage 1 is meaningless without it).
