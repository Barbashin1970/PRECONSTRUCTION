# Нужен ли ИИ В продукте? Критерии

Это **ключевой и самый недооценённый этап** пресейла (этап 4 в
[5 этапах](02-presale-5-stages.md)). Цель — **честно** ответить, нужен ли ИИ внутри
финального продукта, а не «как бы покрасивее вставить ИИ».

> **Главный принцип.** Не все проекты должны содержать ИИ. Многие отличные ИТ-решения в
> строительстве **создаются С ПОМОЩЬЮ ИИ**, но работают на классических технологиях.

## Различие: «С помощью ИИ» vs «С ИИ внутри»

| | Создано **С ПОМОЩЬЮ** ИИ | Содержит ИИ **ВНУТРИ** |
|---|---|---|
| Что это | Использовали ChatGPT/Copilot/Cursor для написания кода (вайб-кодинг) | В продакшене работают ML-модели, API к LLM, embeddings search |
| Финальный продукт | Классическое приложение | ИИ — часть рантайма |
| Пример | Калькулятор смет, написанный с ИИ, но считающий по формулам | Интеллектуальный поиск по регламентам через embeddings |

Путать эти две вещи — корневая ошибка. На питче за это отвечает обязательный слайд
«Применимость ИИ» (см. [05](05-pitch-packaging.md)).

## Когда ИИ ДЕЙСТВИТЕЛЬНО нужен в продукте

- Неструктурированные данные: тексты, изображения, видео.
- Обучение на больших данных.
- Распознавание паттернов, которые сложно формализовать правилами.
- Генеративные задачи (создание контента, планировок).
- Персонализация на основе поведения пользователей.
- Предсказательная аналитика.

## Когда достаточно КЛАССИЧЕСКИХ методов

- Чёткие правила и логика.
- Детерминированные вычисления.
- CRUD-операции с БД.
- Простая фильтрация и сортировка.
- Калькуляторы по формулам.
- Агрегация структурированных данных.

## Протокол честной оценки (5 вопросов)

1. Можно ли решить задачу **классическими** методами (БД, правила, алгоритмы)?
2. Если да — в чём преимущество ИИ-подхода? Оправдана ли доп. сложность?
3. Если нет — какие **конкретно** задачи ТРЕБУЮТ ИИ/ML?
4. Различи: что **создать** с помощью ИИ, а что должно **содержать** ИИ в финале?
5. Рекомендация: нужен ли ИИ в финале и в каких компонентах?

## Примеры решений

| Задача | Вердикт |
|---|---|
| Парсинг документов | С ПОМОЩЬЮ ИИ один раз → дальше обычная БД ✓ |
| Интеллектуальный поиск по регламентам | ДА, нужен embedding search с ИИ ✓ |
| Калькулятор стоимости по параметрам | НЕТ, достаточно формул и правил ✓ |
| Генерация планировок | ДА, нужен generative AI ✓ |
| Распознавание размеров на чертежах | НЕТ для LLM → специализированное компьютерное зрение (см. [07](07-case-llm-limits.md)) ✓ |

> На хакатоне выше всего оценивается **честность** этой оценки, а не «крутость ИИ».
> Признать, что классика лучше, — сильный, а не слабый ход.
