# Программа очного мини-хакатона для студентов НГАУДИ

**Концепция:** «Продакт-менеджмент (пресейл) строительных проектов с ИИ-помощниками».

## Ключевая идея

Мероприятие **не о внедрении ИИ в финальный продукт**, а о том, как использовать ИИ
**на исследовательской стадии (пресейл)** для проработки, анализа и упаковки проектных
идей. Многие современные ИТ-решения в строительстве **создаются с помощью ИИ** (например,
через вайб-кодинг), но **сами не используют ИИ** в коде финальной версии.

> **Главное послание.** ИИ — мощный инструмент для этапа исследований и пресейла, а не
> обязательный компонент каждого проекта.

## Двойной пресейл в ИТ-проектах для строительства

Когда речь об ИТ-проектах ДЛЯ строительства (цифровой мастер-план, ГИС-платформа,
система анализа регламентов), происходит **двойной пресейл**:

- **Уровень 1 — пресейл строительного решения:** какую проблему в строительстве решаем?
  Кто ЦА (градостроители, застройщики, муниципалитеты)? Как вписывается в строительный цикл?
- **Уровень 2 — пресейл ИТ-решения:** какая техническая архитектура? Какие технологии?
  **Нужен ли ИИ в продукте?**

> **Вывод.** Пресейл в ИТ и прекострукшн в строительстве — это одна фаза жизненного цикла
> под разными названиями. Обе включают исследование, проектирование, оценку и планирование
> ДО начала реализации.

### Таблица аналогии: ИТ-пресейл ↔ строительный прекострукшн

| Аспект | ИТ-проект (Pre-Sales) | Строительный проект (Pre-Construction) |
|---|---|---|
| Название фазы | Pre-Sales / Presale | Pre-Construction / Preconstruction |
| Главная цель | Понять требования клиента, предложить техрешение | Понять потребности заказчика, создать план стройки |
| Анализ осуществимости | Feasibility Assessment (техническая реализуемость) | Feasibility Study (целесообразность строительства) |
| Исследование контекста | Анализ ИТ-инфраструктуры клиента | Инспекция участка: территория, почвы, экология |
| Проектирование решения | Solution Architecture: технологии, стек | Design Development: чертежи, инженерные системы |
| Регуляторика | Compliance (GDPR, безопасность данных) | СП, ГОСТ, разрешения |
| Оценка стоимости/сроков | Estimation: трудозатраты, timeline | Cost Estimation: смета, календарный план |
| Подбор команды | Состав команды разработки | Подрядчики, инженеры |
| Анализ рисков | Технические риски, риски интеграции | Строительные риски, природные факторы |
| Демонстрация концепции | POC, демо продукта | Визуализация, макеты, 3D-модели |
| Создание предложения | Коммерческое предложение, roadmap, бюджет | Тендерная документация: проект, смета, график |
| Результат фазы | Контракт на разработку → Delivery | Контракт с подрядчиком → Construction |

## Структура мероприятия (4–5 часов)

### Блок 1. Введение в пресейл-методологию с ИИ (60 мин)

- **1.1 Открытие и контекст (15 мин).** Ледбрейкер, команды по 5–6 человек (8–10 команд).
  Ключевой тезис: «Сегодня мы НЕ учимся встраивать ИИ в проекты. Мы учимся использовать ИИ
  как инструмент продакт-менеджера на этапе пресейла — для исследования, анализа и упаковки идей».
- **1.2 Презентация «Пресейл-цикл проекта с ИИ-ассистентами» (45 мин).** 5 этапов пресейла
  (см. ниже), демонстрация на кейсе «Цифровая платформа для анализа градостроительных
  регламентов», обзор бесплатных ИИ-инструментов, введение в Perplexity Spaces.

### Блок 2. Самоэкспертиза проектов через ИИ-агенты (150 мин)

- **2.1 Формулирование идей (20 мин).** Каждая команда выбирает идею из
  архитектуры/строительства (2–3 предложения, проработанность не важна).
- **2.2 Создание Perplexity Space и загрузка инструкций (15 мин).** Загрузка 4 PDF-инструкций,
  настройка Custom Instructions для ролевых ИИ-агентов, приглашение команды в Space.
- **2.3 Пресейл-анализ через ИИ-агенты (90 мин).** Команды проходят 5 этапов, по отдельному
  треду на этап (промпты — см. ниже).
- **2.4 Создание презентации (25 мин).** Gamma.app / Canva / Google Slides + ChatGPT / ГигаЧат.

### Блок 3. Питчи и обратная связь (60 мин)

- **3.1 Командные питчи (40 мин).** 5 минут на команду: 4 мин презентация + 1 мин
  обязательный слайд «Применимость ИИ».
- **3.2 Экспертная обратная связь (15 мин).** Конструктивная критика. Особо ценятся кейсы,
  где команда честно признала, что классический подход лучше ИИ.
- **3.3 Закрытие (5 мин).**

## 5 этапов пресейла

**Этап 1. Идентификация проблемы и возможности.** Какую проблему решает проект? Кто
благополучатели? ИИ: анализ рынка, поиск аналогов, тренды.

**Этап 2. Бизнес-анализ.** Анализ рынка и конкурентов, оценка жизнеспособности. ИИ: парсинг
рыночных данных, SWOT, финансовое моделирование.

**Этап 3. Техническая экспертиза.** Техническая реализуемость, регуляторные требования,
техстек. ИИ: анализ нормативов, подбор инструментов, feasibility.

**Этап 4. Системный анализ применимости ИИ (КЛЮЧЕВОЙ).** Нужен ли ИИ В САМОМ ПРОДУКТЕ?
Различие «создано С ПОМОЩЬЮ ИИ» vs «продукт С ИИ ВНУТРИ». Когда ИИ реально нужен, а когда нет.

**Этап 5. Упаковка и питчинг.** Презентация для стейкхолдеров, ценностное предложение,
визуализация. ИИ: генерация презентаций, визуализаций, текстов.

### Демонстрационный кейс: «Цифровая платформа анализа градостроительных регламентов»

1. **Идентификация (Perplexity):** «Проанализируй проблемы градостроителей при работе с
   регламентами в России. Найди статистику ошибок и временных затрат».
2. **Бизнес-анализ (Perplexity):** «Найди аналоги на рынке. Сделай SWOT. Оцени размер рынка
   градостроительных услуг в РФ».
3. **Техэкспертиза (DeepSeek):** «Какие технологии используются для парсинга PDF с
   регламентами? Какие есть отечественные ГИС-платформы? Проанализируй ФЗ-218».
4. **Применимость ИИ (DeepSeek + критика):** «Нужен ли ИИ В САМОЙ платформе или достаточно
   классической БД с поиском?» → Вывод: «Парсинг можно сделать С ПОМОЩЬЮ ИИ один раз, но
   платформа работает на обычной БД. ИИ в продукте нужен только для интеллектуального
   поиска — опционально».
5. **Упаковка (ГигаЧат):** структура презентации, визуализации, elevator pitch.

## Промпты по этапам (треды в Space)

**Тред 1 «Анализ проблемы»** (Роль: Бизнес-аналитик):
> 1. Опиши, кто сталкивается с этой проблемой (ЦА). 2. Оцени масштаб (сколько
> людей/организаций). 3. Найди статистику по временным/финансовым потерям. 4. Укажи
> корневые причины. 5. Приведи реальные кейсы. Используй файл «Инструкция_Бизнес-аналитик.pdf».

**Тред 2 «Анализ рынка и конкурентов»** (Бизнес-аналитик + Маркетолог):
> 1. Найди существующие решения (аналоги, конкуренты). 2. Сделай SWOT нашей идеи на фоне
> конкурентов. 3. Оцени размер рынка РФ (TAM, SAM, SOM). 4. Определи потенциальных
> заказчиков. 5. Предложи модели монетизации.

**Тред 3 «Технологический анализ»** (Системный аналитик ИИ):
> 1. Какие технологии нужны (языки, фреймворки, БД)? 2. Какие готовые библиотеки/API есть?
> 3. Регуляторные ограничения, нормативы? 4. Сложность разработки (простая/средняя/высокая).
> 5. Риски технической реализации.

**Тред 4 «Нужен ли ИИ В продукте?»** (Системный аналитик ИИ, критическое мышление) — ЧЕСТНО:
> 1. Можно ли решить задачу КЛАССИЧЕСКИМИ методами (БД, правила, алгоритмы)? 2. Если да — в
> чём преимущество ИИ? Оправдана ли сложность? 3. Если нет — какие задачи ТРЕБУЮТ ИИ/ML?
> 4. Различи: что СОЗДАТЬ с помощью ИИ, а что должно СОДЕРЖАТЬ ИИ в финале. 5. Рекомендация:
> нужен ли ИИ в финальном решении и в каких компонентах?

Примеры выводов: «Парсинг документов — с помощью ИИ один раз, дальше обычная БД» ✓;
«Интеллектуальный поиск по регламентам — ДА, нужен embedding search» ✓; «Калькулятор
стоимости — НЕТ, достаточно формул» ✓; «Генерация планировок — ДА, generative AI» ✓.

**Тред 5 «Создание презентации»** (Упаковщик питча) на основе тредов 1–4:
> 1. Elevator pitch (30 сек). 2. Структура презентации на 5 минут: Проблема / Решение /
> Почему мы / Технология (НУЖЕН ЛИ ИИ ВНУТРИ) / Рынок и монетизация / Roadmap. 3. Ключевые
> слайды. 4. Ключевые цифры.

## Бесплатные ИИ-инструменты

- **DeepSeek** (бесплатно) — техническая точность, reasoning (DeepSeek-R1), код, математика.
  Минусы: нет голоса, нет картинок, базовый интерфейс. `deepseek.com`.
- **GigaChat** (бесплатно для физлиц) — русский язык, строительная терминология, контекст
  российских нормативов, генерация картинок (Kandinsky) и презентаций на 12 слайдов. `giga.chat`.
- **Perplexity** (ограниченный бесплатный) — поиск с источниками, актуальные данные.
  Бесплатно: 5 запросов / 4 часа. Доступен в РФ. Pro $20/мес (GPT-4, Claude). `perplexity.ai`.

### Perplexity Spaces как инструмент командной работы

- Создать Space для проекта; загрузить PDF-инструкции; задать **Custom Instructions** для
  ИИ-агентов (бизнес-аналитик, маркетолог, системный аналитик); совместная работа команды.

Пример Custom Instructions:
> «Ты работаешь в роли, указанной в начале каждого запроса (Бизнес-аналитик / Маркетолог /
> Системный аналитик ИИ / Упаковщик питча). Используй загруженные в Space файлы как
> справочники с методологией. Всегда: опирайся на реальные данные (ищи источники),
> структурируй ответы, давай конкретные рекомендации, указывай источники».

## 4 PDF-инструкции (роли-агенты)

### 1. Инструкция_Бизнес-аналитик.pdf

- Методология **BANT** (Budget, Authority, Need, Timing) для квалификации идей.
- Фреймворк анализа проблемы **4Ws** (Who, What, Where, Why).
- Промпты рыночного анализа, шаблоны **SWOT**, методы оценки рынка **TAM/SAM/SOM**.

### 2. Инструкция_Маркетолог.pdf

- Определение ЦА, конкурентная разведка, **Customer Journey Mapping**.
- Промпты для поиска кейсов и отзывов, стратегии монетизации SaaS/B2B.

### 3. Инструкция_Системный_аналитик_ИИ.pdf

**Часть А — техэкспертиза:** оценка реализуемости, анализ СП/ГОСТ/ФЗ, подбор стека, риски.

**Часть Б — критерии необходимости ИИ (КРИТИЧЕСКИ ВАЖНО):**

*Когда ИИ ДЕЙСТВИТЕЛЬНО НУЖЕН в продукте:* неструктурированные данные (тексты, изображения,
видео); обучение на больших данных; распознавание паттернов, сложных для формализации;
генеративные задачи; персонализация по поведению; предсказательная аналитика.

*Когда достаточно КЛАССИЧЕСКИХ методов:* чёткие правила и логика; детерминированные
вычисления; CRUD; простая фильтрация/сортировка; калькуляторы по формулам; агрегация
структурированных данных.

*Различие «С помощью ИИ» vs «С ИИ внутри»:* «С помощью ИИ» — использовали
ChatGPT/Copilot/Cursor для написания кода, но финал — классическое приложение; «С ИИ внутри» —
в продакшене работают ML-модели, API-вызовы к LLM, embeddings search.

### 4. Инструкция_Упаковка_питча.pdf

Структура (Problem-Solution-Market-Tech-Team), elevator pitch (30 сек), storytelling,
визуализация, работа с возражениями.

**Шаблон питча:**
```
[ПРОБЛЕМА] Кто: [ЦА]. Страдает от: [проблема]. Масштаб: [цифры].
[РЕШЕНИЕ] Мы предлагаем: [суть в 1 предложении]. Как работает: [кратко]. Преимущество: [vs альтернативы].
[ТЕХНОЛОГИЯ] Стек: [технологии]. КРИТИЧЕСКИ: ИИ в продукте — [ДА/НЕТ + обоснование].
  Если ДА: где именно и почему необходим. Если НЕТ: как решается без ИИ и почему оптимально.
[РЫНОК] Размер TAM/SAM. Монетизация: [модель]. Конкуренты: [отличие].
[ROADMAP] Шаг 1 → Шаг 2 → Шаг 3.
```

## Критерии оценки питчей

1. Глубина проработки (25%) — как пройдены все этапы пресейла.
2. Качество использования ИИ-инструментов (20%) — эффективность работы с Perplexity Spaces.
3. **Критическое мышление (20%)** — честность оценки необходимости ИИ в продукте.
4. Презентация и подача (20%).
5. Практическая ценность идеи (15%).

> **Важно.** Оценивается НЕ «насколько крутой ИИ в проекте», а насколько **обоснованно**
> принято решение о необходимости/отсутствии ИИ.

---

## Ключевые выводы

1. ИИ — инструмент исследований, а не обязательный компонент каждого проекта.
2. Вайб-кодинг: многие ИТ-решения СОЗДАЮТСЯ с помощью ИИ, но работают без него.
3. Пресейл-методология с ИИ-ассистентами ускоряет проработку идей в 5–10 раз.
4. Perplexity Spaces — мощный инструмент командной работы.

**Было → Стало:** фокус сместился с «как встроить ИИ в проект» на «как использовать ИИ для
проработки идеи на этапе пресейла»; добавлено критическое мышление (ИИ не всегда нужен) и
различение «создано С ПОМОЩЬЮ ИИ» (вайб-кодинг) vs «содержит ИИ ВНУТРИ» (ML в продакшене).
